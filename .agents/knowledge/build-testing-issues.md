# Build, Bundling & Testing Knowledge Memory

Curated lookup of verified gotchas, anti-patterns, and proven fixes for Angular builds, bundle budget limits, and Karma/Jasmine unit testing.

---

### 1. Component CSS Exceeding Maximum Budget Warning
- **Symptom**: Build prints `▲ [WARNING] ...component.css exceeded maximum budget. Budget 15.00 kB was not met...`.
- **Root Cause**: Inlining large SVG base64 strings, duplicating Material typography rules, or pasting large resets inside component-scoped stylesheets.
- **Proven Fix**:
  ```diff
  // 1. Move reusable typography/layout classes to src/styles.css
  // 2. Reference SVG icons by icon font or external assets rather than base64 inline strings
  // 3. If a complex form legitimately requires a higher budget, adjust in angular.json:
  "budgets": [
    {
      "type": "componentStyle",
  -   "maximumWarning": "15kB",
  +   "maximumWarning": "25kB"
    }
  ]
  ```

### 2. Mocking Autogenerated API Services in Unit Specs
- **Symptom**: `NullInjectorError: No provider for HttpClient!` during unit tests for components injecting autogenerated API services.
- **Root Cause**: The generated service requires `ApiConfiguration` and `HttpClient`, which are not automatically provided in `TestBed.configureTestingModule`.
- **Proven Fix**:
  ```typescript
  import { TestBed } from '@angular/core/testing';
  import { provideHttpClient } from '@angular/common/http';
  import { provideHttpClientTesting } from '@angular/common/http/testing';
  import { CustomerService } from '../../../api/services';
  import { of } from 'rxjs';

  describe('CustomerListComponent', () => {
    let mockCustomerService: jasmine.SpyObj<CustomerService>;

    beforeEach(() => {
      mockCustomerService = jasmine.createSpyObj('CustomerService', ['customersGetAll']);
      mockCustomerService.customersGetAll.and.returnValue(of([]));

      TestBed.configureTestingModule({
        providers: [
          provideHttpClient(),
          provideHttpClientTesting(),
          { provide: CustomerService, useValue: mockCustomerService }
        ]
      });
    });
  });
  ```

### 3. Missing Track Expression in Modern `@for` Blocks
- **Symptom**: Angular compiler warning or performance degradation when table/list rows re-render from scratch on every change detection cycle.
- **Root Cause**: Modern Angular requires an explicit `track` expression for all `@for` loops to identify DOM nodes uniquely.
- **Proven Fix**:
  ```diff
  // WRONG: Untracked or tracking index when unique ID exists
  - @for (customer of customers(); track $index)

  // CORRECT: Track unique primary key
  + @for (customer of customers(); track customer.id)
  ```
