## 🔭 Skill Scout Recommendation: Angular 19 httpResource / resource() API

- **Priority**: `🟡 Recommended`
- **Logged**: 2026-09-26
- **What it is**: Angular 19's native asynchronous data-loading primitive that bridges reactive signals directly with HTTP requests.
- **What problem it solves**: Currently, services and components manually subscribe to RxJS Observables, manage cancellation with `takeUntilDestroyed()`, and manually set local signals for loading/error/value states. `httpResource()` handles loading, error, and value states automatically as signals.
- **Current state in our repo**: Components inject autogenerated API services and call `.subscribe()` or use `toSignal()`, managing loading flags manually.
- **How to adopt it**:
  1. For new data-fetching endpoints, create wrapper functions using `httpResource()`.
  2. Consume `.value()`, `.isLoading()`, and `.error()` signals directly in templates.
  3. Estimated effort: ~2 hours per feature area.
  4. Blast radius: Page container components and data services.
- **Risk assessment**: Low risk; fully interoperable with existing RxJS services.
- **Source**: [Angular.dev — Resource API](https://angular.dev/guide/signals/resource)

## 🔭 Skill Scout Recommendation: Angular 19 linkedSignal() for Local Override State

- **Priority**: `🟡 Recommended`
- **Logged**: 2026-09-26
- **What it is**: Angular 19 reactive primitive for state that resets whenever a source signal changes, but can be locally updated without breaking reactivity.
- **What problem it solves**: In detail and edit forms (e.g. customer details, loan calculator), fields need to initialize from route params or loaded customer data, but allow user modification. Previously required awkward `effect()` or manual synchronization.
- **Current state in our repo**: Edit screens initialize form controls in `ngOnInit()` or use manual subscriptions.
- **How to adopt it**:
  1. Replace manual state copies with `readonly localField = linkedSignal(() => this.sourceData()?.field)`.
  2. Estimated effort: ~1 hour per form component.
  3. Blast radius: Detail and form components.
- **Risk assessment**: Minimal risk; simplifies component state and prevents out-of-sync bugs.
- **Source**: [Angular.dev — linkedSignal](https://angular.dev/api/core/linkedSignal)

## 🔭 Skill Scout Recommendation: HttpOnly/Secure Cookie Refresh Token Flow

- **Priority**: `🔴 Critical`
- **Logged**: 2026-09-26
- **What it is**: Secure browser session lifecycle storing refresh tokens in an `HttpOnly`, `Secure`, `SameSite=Strict` cookie, keeping only short-lived access tokens in memory.
- **What problem it solves**: Flags from `CODE-REVIEW.md` (Finding 1 & 2): tokens stored in `localStorage` are vulnerable to XSS exfiltration, and 401 interceptor currently logs out immediately rather than initiating a single-flight token refresh.
- **Current state in our repo**: `auth.service.ts` writes tokens to `localStorage` and logs authentication details to console.
- **How to adopt it**:
  1. Remove sensitive token logging from `auth.service.ts` and `auth.interceptor.ts`.
  2. Align with backend `RefreshToken` endpoint to support HttpOnly cookie exchange.
  3. Implement single-flight refresh queue in `auth.interceptor.ts`.
  4. Estimated effort: ~4 hours.
  5. Blast radius: `src/app/core/services/auth.service.ts`, `src/app/core/interceptors/auth.interceptor.ts`.
- **Risk assessment**: Medium; requires coordinated backend testing.
- **Source**: [OWASP Token Storage Best Practices](https://cheatsheetseries.owasp.org/cheatsheets/JSON_Web_Token_for_Java_Cheat_Sheet.html)

## 🔭 Skill Scout Recommendation: Incremental Deferrable Views (@defer) on Heavy Tables

- **Priority**: `🟢 Nice-to-have`
- **Logged**: 2026-09-26
- **What it is**: Angular's built-in `@defer (on viewport)` block that defers bundle loading and rendering of below-the-fold components until visible.
- **What problem it solves**: Heavy customer ledger tables, loan schedules, and analytics charts currently load eagerly in route bundles, increasing initial route transition times.
- **Current state in our repo**: All components in feature routes are eagerly loaded inside their parent template.
- **How to adopt it**:
  1. Wrap heavy sub-components in `@defer (on viewport) { <app-heavy-table /> } @placeholder { <app-table-skeleton /> }`.
  2. Estimated effort: ~1.5 hours across pages.
  3. Blast radius: Page templates.
- **Risk assessment**: Very low; transparent optimization.
- **Source**: [Angular.dev — Deferrable Views](https://angular.dev/guide/defer)
